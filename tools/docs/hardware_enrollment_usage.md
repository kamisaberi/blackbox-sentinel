The hardware identity token generated by `sentinel-ctl hardware enroll` (`/etc/sentinel/hardware_identity.token`) serves as the **Physical Silicon Fingerprint** for your edge appliance.

Here are the **3 primary ways the token is used across the ecosystem**:

---

### 1. Hardware License Binding & Anti-Cloning Protection

When `blackbox-sentinel` daemon or `libblackbox.so` starts up, `TpmEnrollmentManager::verify_hardware_token()` runs automatically:

```text
  [Daemon Launch] ──> [Query /dev/tpmrm0 & DMI UUID] ──> [Compare against /etc/sentinel/hardware_identity.token]
                                                                  │
                    ┌─────────────────────────────────────────────┴─────────────────────────────────────────────┐
                    ▼                                                                                           ▼
          [MATCH: VERIFIED]                                                                           [MISMATCH: CLONED VM]
  • Enables active eBPF drops (< 0.84 µs)                                                     • Locks eBPF active drops
  • Loads full 30 dissectors                                                                  • Falls back to restricted mode
```

#### How to test anti-cloning verification:
```bash
# Verifies if current silicon matches stored token
sentinel-ctl hardware status
```
* **On genuine enrolled machine:** Displays `[VERIFIED] Token Binds to Silicon`.
* **If disk image is copied to a different VM/machine:** Displays `[UNVERIFIED] Hardware Mismatch` and restricts inline eBPF drops.

---

### 2. Fleet Enrollment & Zero-Touch Provisioning (ZTP)

When registering a new edge node with **`sentinel-nexus`** (the central C2 command plane):

1. `sentinel-ctl` reads `hardware_token_hash` from `/etc/sentinel/hardware_identity.token`.
2. It sends the hardware hash during the gRPC ZTP handshake (`ZtpTokenAgent`).
3. `sentinel-nexus` validates the hardware hash against the authorized customer node database before broadcasting signed `.spkg` packages or AI models to that node.

```bash
# Register appliance with Nexus C2 using physical hardware token
sentinel-ctl sync --routes /etc/sentinel/model_routes.yaml
```

---

### 3. Air-Gapped USB Sneakernet Asset Encryption

For water treatment plants or power substations with zero internet access, you can lock offline USB deployment bundles specifically to an authorized hardware token:

```bash
# Export offline cache bundle bound to hardware token
sentinel-ctl cache export /tmp/sentinel_offline_bundle.tar.gz

# On air-gapped target machine: Import bundle
sentinel-ctl cache import /tmp/sentinel_offline_bundle.tar.gz
```
